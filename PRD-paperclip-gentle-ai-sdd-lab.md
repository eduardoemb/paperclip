## 1. Executive decision

This PRD proposes an isolated, reversible local lab in which Paperclip manages the task and business state, while OpenCode runs a single Paperclip agent and Gentle AI retains exclusive authority over the internal SDD cycle.

This PRD defines **all project work**, including Paperclip installation, prerequisites, dependencies, embedded database, local configuration, operational commands, and validation. Paperclip is not treated as a preinstalled dependency: its functional installation is one of the primary deliverables.

The target flow is:

```text
Paperclip task
  → opencode_local
  → OpenCode: sdd-orchestrator-high
  → Gentle AI: propose → spec → design → tasks → apply → verify → archive
  → human review in Paperclip
  → done
```

The recommendation is to **approve the lab with preflight gates**. Engram is healthy in the Gate A inspection. The lab is not yet ready to install because an executable Node.js 20 does not exist at the pinned path, `pnpm` is unavailable, and the presentation/resumption of blocking questions must be tested end to end in Paperclip.

### Expected result

At the end of the test, reproducible evidence must exist that:

1. Paperclip was installed from the official source pinned to an approved commit.
2. Its dependencies, CLI, UI/API, and embedded PostgreSQL are operational without requiring an external database.
3. Reproducible procedures exist for starting, stopping, diagnosing, and uninstalling the lab.
4. Paperclip woke the correct agent through assignment or manual execution.
5. The primary process was exactly `sdd-orchestrator-high`.
6. That orchestrator processed the eight SDD phases internally without creating Paperclip or OpenCode agents per phase.
7. The models, variants, permissions, skills, and MCP filters resolved by OpenCode were preserved.
8. A small task completed `propose/spec/design/tasks/apply/verify/archive`.
9. A blocking question was displayed in full and the human response resumed the same session.
10. Paperclip did not reach `done` until a human review checked valid `verify` and `archive` evidence.
11. The rollback removed only the lab, without modifying Zeler Director or the functional Gentle AI/OpenCode configuration.

## 3. Problem and motivation

Paperclip and Gentle AI operate at different levels and can complement each other, but they can also compete if their responsibilities are confused:

- Paperclip manages the company, objectives, projects, tasks, agents, workspaces, budgets, executions, and human review.
- Gentle AI manages the sequence, dependencies, persistence, and authority of SDD phases.
- OpenCode is the runtime that resolves the primary agent, its tools, models, permissions, plugins, and MCPs.

The problem to solve is not merely “make Paperclip open OpenCode.” It is to demonstrate that Paperclip can wrap a complete SDD execution without changing its internal topology, degrading the primary HIGH profile, or confusing process success with valid change completion.

## 4. User and main flow

### Primary user

Human lab operator who creates and assigns the task, responds to blocking decisions, reviews the final evidence, and executes rollback.

### Happy path

1. The operator starts Paperclip in isolated local mode.
2. Creates a lab company, an objective, a project, a workspace, and a single CEO agent.
3. The workspace points exactly to the target repository.
4. The operator creates a small task with the four SDD preflight decisions already explicit to avoid an unnecessary initial pause.
5. The assignment wakes the CEO through `opencode_local`.
6. Paperclip runs OpenCode with `--agent sdd-orchestrator-high`.
7. Gentle AI executes and validates each HIGH phase according to its dependency graph.
8. Artifacts are persisted in Engram; a separate test validates OpenSpec.
9. The agent publishes `verify` and `archive` evidence and requests transition to review.
10. Paperclip intercepts completion, keeps the task in `in_review`, and waits for the operator.
11. The operator verifies the evidence and approves; only then does the task reach `done`.

### Blocking flow

1. Gentle AI produces a complete blocking decision envelope.
2. Because `opencode run` is non-interactive, the agent does not use the native `question` UI.
3. The lab-specific instruction creates an equivalent Paperclip interaction in the task and preserves order, options, descriptions, response domain, and blocking reason.
4. The task remains in `in_review`, not `done`.
5. The human responds in Paperclip.
6. `continuationPolicy: wake_assignee` wakes the same agent.
7. Paperclip resumes the same OpenCode session ID and Gentle AI continues without repeating completed phases.

## 8. Functional requirements

### FR-1. Isolated installation

The project must install Paperclip from the official repository pinned to an approved commit. It must validate Node.js 20+, pnpm 9.15+, install dependencies with the lockfile, complete onboarding, start the CLI/UI/API, and verify embedded PostgreSQL. Paperclip must be startable and stoppable through documented commands. Its instance data must live in a dedicated lab directory outside the global OpenCode configuration.

Installation passes only if an operator can repeat it from a clean Git folder by following the documented procedure, without depending on hidden state from this session.

### FR-2. Minimum topology

Exactly one Paperclip agent and one OpenCode agent must exist for the initial flow: the CEO. SDD phases remain internal states of Gentle AI.

### FR-3. Primary selection

Every execution must record arguments that include `--agent sdd-orchestrator-high`. The name's presence in configuration is insufficient: the transcript must demonstrate that no fallback occurred.

### FR-4. Profile preservation

Execution must preserve the primary HIGH profile's model, variant, mode, tool allowlist, and permissions. Validation compares snapshots before and during the test.

### FR-5. Complete SDD cycle

The E2E task must produce identifiable evidence of proposal, spec, design, tasks, apply-progress, verify-report, and archive-report.

### FR-6. Persistence

The main flow uses `engram` only after the handshake is correct. An independent test uses `openspec`. Combined mode remains blocked until `both`/`hybrid` compatibility is resolved or demonstrated.

### FR-7. Questions and consent

Every blocking question must preserve the complete envelope. If it fits in a Paperclip interaction, use `ask_user_questions` or `request_confirmation`; otherwise, publish it in full in the thread, state the valid response syntax, and leave the task explicitly waiting.

### FR-8. Resumption

After a human response, the next execution must use the same `sessionId`, the same `cwd`, and the same primary agent. It must not recreate already valid artifacts.

### FR-9. Final state

The agent must never request `done` before it has a valid `verify-report`, no open critical findings, and a valid `archive-report`. Paperclip must intercept the request and apply human review before the terminal state.

### FR-10. Resumable failures

A model, MCP, permission, timeout, process, or artifact failure must leave a transcript, state, and next action. `run: succeeded` and a partial response do not equal task completion.

## 9. Non-functional requirements

- **Isolation:** no writes outside the target repository, the Paperclip lab's own data, normal OpenCode session stores, and Engram stores.
- **Least privilege:** no `dangerouslySkipPermissions` initially; no global expansion of MCP or tools.
- **Reproducibility:** the Paperclip commit, versions, commands, configuration, and results must be recorded.
- **Observability:** retain the task ID, run ID, session ID, phase, artifact, and human decision.
- **Reversibility:** rollback by allowlist; never delete broad paths or global configuration.
- **Cost control:** small and explicit budget; no scheduled wakeups or unlimited retries.
- **Privacy:** secrets only through Paperclip/OpenCode mechanisms; never in tasks, prompts, versioned files, or deliverable logs.
- **Fail closed:** any uncertainty about the profile, permissions, artifacts, or session stops progress.

## 10. State model and definition of `done`

```text
backlog → todo → in_progress
                       ├─→ blocked → todo/in_progress
                       └─→ in_review → done
```

The internal SDD execution is reflected as evidence, not as new Paperclip states:

```text
in_progress
  proposal
  spec
  design
  tasks
  apply
  verify
  archive
  → in_review
  → human approval
  → done
```

### Mandatory definition of `done`

A task may reach `done` only when the human review confirms, in the same thread:

- primary profile `sdd-orchestrator-high`;
- IDs or paths for all required artifacts;
- current `verify-report` with no open CRITICAL findings;
- current `archive-report`;
- all implementation tasks complete or reconciled with evidence;
- no pending question, consent, permission, or session;
- the change is limited to the target repository;
- Zeler Director was not modified;
- the approval comment contains the result of the preceding list.

Paperclip can enforce human review and approval, but **it has not been verified to understand Gentle AI artifacts semantically**. In this first version, checking `verify` and `archive` is an explicit responsibility of the human reviewer.

## 11. Security, permissions, secrets, and isolation

1. Start Paperclip only on loopback/trusted-local for the test.
2. Use an exclusive `PAPERCLIP_HOME` and `instanceId` for the lab.
3. Do not store tokens or credentials inside the repository.
4. Do not manually copy or regenerate the global Gentle AI configuration.
5. With `dangerouslySkipPermissions: false`, treat any permission request as a blocker; `opencode run` may automatically reject it.
6. Do not change it to `true` during the test without human approval that identifies the required permission and the effective diff of the temporary configuration.
7. Do not sync Paperclip skills to `~/.claude/skills` on the first run.
8. Capture before/after snapshots of the resolved configuration for the primary HIGH profile and visible MCPs.
9. Do not activate periodic heartbeats.
10. Configure the agent budget at the minimum sufficient for one test; any increase requires approval.

Rollback must be prepared before the first execution and use an exact allowlist.

1. Pause the CEO agent and stop Paperclip.
2. Export IDs, configuration, and evidence required for audit, without secrets.
3. Delete the lab company/instance or remove only its dedicated data directory.
4. Remove `node_modules` and other installation artifacts only if a complete uninstall is requested, using exact paths within the checkout.
5. Delete only the files created for the E2E test through an explicit reviewed list.
6. Delete `paperclip-lab-agent.md` only if the lab is being closed; preserve this PRD.
7. Verify that no new Paperclip symlinks exist in `~/.claude/skills`.
8. Do not delete or regenerate `~/.config/opencode`, `~/.agents`, Engram, or Gentle AI.
9. Run again:

```sh
gentle-ai doctor
/Users/eduardoramirez/.opencode/bin/opencode debug agent sdd-orchestrator-high
```

10. Confirm that the target repository is clean except for explicitly preserved files.
11. Confirm that Zeler Director has no changes.

## 17. Go/no-go gates

### Go

- Official repository and pinned commit.
- Healthy Paperclip doctor.
- Healthy Gentle AI doctor in the real environment.
- Connected Engram.
- HIGH matrix with no unapproved drift.
- Correct adapter Environment test.
- Reviewed bridge instruction.
- Active human execution policy.
- Limited budget and wakeups.

### No-go

- Primary agent fallback.
- Disconnected Engram for the Engram flow.
- Unexpected expansion of tools/MCP.
- Need to modify Gentle AI.
- Truncated question or no resumption path.
- Different session ID after the human response.
- `done` without verifiable verify/archive.
- Writes outside the allowlist.

## 18. Approval-blocking question

Is it accepted that, in this first version, the guarantee of “no `done` before `verify` + `archive`” will be implemented through a Paperclip execution policy with **mandatory human approval and an evidence checklist**, rather than automatic validation of Gentle AI artifacts inside Paperclip?

If the answer is no, the scope changes materially: an additional adapter, plugin, or semantic gate would need to be developed, which contradicts the initial scope of “do not modify Paperclip/Gentle AI; only install, configure, and validate.”
